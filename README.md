# Sign Editor GUI (Command Support)

> Some parts of the code were generated by AI and has been reviewed by human. 一些代码经过 AI 修改。已经过人工复核。

## Feature

Allow players to modify the sign style and commands in the GUI.

The **OP features** switch in the footer is the sign's own `allow_op_features` flag, the one vanilla uses to decide whether a sign parses its text components and whether their click commands may run.
The editor reads it from the sign when a side is loaded, sends the switch's value back with the update, and the server stores it, so it is a property of the sign rather than a setting of the window. It turns itself on when you type a command or a raw component, and can be switched off again
by hand.

The **Waxed** switch beside it is the sign's own `is_waxed` flag — the state a honeycomb leaves behind. It is stored on the block entity rather than in the block state, and reached through the game's own `isWaxed()` / `setWaxed(boolean)`, so the editor reads it straight off the sign and the
server just calls the setter. While it is on the sign can no longer be edited by hand — interacting with it plays a failure sound instead of opening the editor — and honeycomb can no longer be applied to it. It does **not** gate click commands: `SignBlock.useWithoutItem` runs them before it ever looks at this flag, and whether a command actually runs is `allow_op_features`' question alone, so the two switches are independent.
